# Законы проекта VR-урок

Эти законы обязательны для любой правки, в любом чате и для любой модели. Если правка нарушает закон, её не делаем и сообщаем Айрату. Изменить, добавить или убрать закон можно только по слову владельца; запись об этом добавляется в «Журнал законов» внизу.

Перед каждым пушем проверить правку по разделу В.

## А. Законы устойчивости

Главное: система не должна рушиться «как домино». Правка одного элемента не ломает остальные.

**А1. Модуль — это граница.** Каждый элемент ядра (темы, меню, личный кабинет ученика, кабинет учителя, кабинет директора, кабинет эксперта, кабинет суперадминистратора, интерфейс, движок, комнаты, редактор комнат, хранилище, синхронизация, права, каталог, справка) — отдельный модуль со своим публичным контрактом: что принимает, что отдаёт, какая версия. Остальные модули знают только контракт, а не внутренности.

**А2. Зависимости идут в одну сторону.** Слои: данные → ядро → модули → интерфейс. Нижний слой не знает о верхнем. Интерфейс не обращается к хранилищу или серверу напрямую, только через ядро. Темы не содержат логики; логика не содержит цветов.

**А3. Сбой модуля не роняет систему.** У каждого модуля своя граница ошибок. При сбое показывается безопасный запасной вид и сообщение «этот раздел временно недоступен», а остальное продолжает работать. Белый экран недопустим. (Прецедент: каждая вкладка учителя уже рисуется в своём `try/catch`.)

**А4. Контракты защищены проверками.** Изменил модуль — проверки контрактов остальных остаются зелёными. Без этого не пушим. Новая функция получает новую проверку на реальных непустых данных.

**А5. Данные проверяются на входе.** Всё, что приходит от пользователя, с сервера, из файла или от другого модуля, проходит схему: неизвестное отбрасывается, лишнее обрезается, пустое заменяется значениями по умолчанию.

**А6. Только совместимые изменения.** Новая версия читает старые данные (миграции). Новые поля необязательны и имеют значение по умолчанию. Данные имеют версию схемы. Старые данные не становятся нечитаемыми.

**А7. Новое включается переключателем.** Каждая крупная функция включается флагом. При сбое выключается флаг, а не откатывается всё.

**А8. Откат всегда возможен.** Рабочие версии сохраняются в релизных ветках, перед миграцией делается копия базы, `main` только вперёд (без force-push).

**А9. Защита от дурака.**
- Опасные действия (удаление, сброс, публикация, смена роли) требуют подтверждения и по возможности обратимы (корзина вместо стирания).
- Ограничения на размеры, длину, частоту запросов.
- Значения по умолчанию безопасны.
- Ошибки объясняются простым языком, без технических деталей, и подсказывают, что делать.
- Нельзя нажать «опубликовать» комнату, которая не прошла проверку; кнопка неактивна и объясняет почему.

**А10. Минимум прав.** Роли: ученик, учитель, директор, эксперт, суперадминистратор. По умолчанию прав нет. Права проверяются на сервере, а не в интерфейсе (спрятанная кнопка — не защита).

**А11. Один источник правды.** У каждой сущности одно место хранения. Логика слияния данных живёт в `js/store.js` (merge) и `server/app.py` (merge_in) и меняется в обоих местах одновременно.

**А12. Безопасный режим.** Если тема, настройка или комната повреждены, загружается встроенная версия. Система всегда запускается.

**А13. Наблюдаемость.** Ошибки пишутся в журнал и видны суперадминистратору. Тихие сбои недопустимы.

**А14. Секреты.** Ключи, пароли, адреса серверов не пишутся в публичные файлы и не просятся в чат. Если ключ случайно попал в чат, его перевыпускают.

**А15. Ничего не удаляется без согласия владельца**: файлы, ветки, данные, базы, артефакты.

**А16. Код автозапуска страницы стоит в конце скрипта; локальные переменные не называются как общие функции; порядок вопросов в `js/questions.js` не меняется** (уроки из `CHECKLIST.md`).

**А17. Иерархия школы неприкосновенна.** Порядок «школа → директор и экспертный совет → учителя → классы → ученики», права сверху вниз и инварианты (последний директор не снимается, классы и ученики архивируются, а не удаляются, критичные действия подтверждаются двумя людьми, всё в журнале аудита) описаны в `docs/ROLES.md` и соблюдаются в любой правке.

## Б. Законы продукта (требования владельца)

Собраны из всех чатов проекта, формулировки владельца сохранены по смыслу. Статусы: **[сделано]**, **[частично]**, **[в плане]**, **[отложено]**, **[процесс]**. Статус обновляется при каждой значимой правке.

**Работа и устройства**
- Б1. Приложение работает автономно на шлеме Oculus Quest (сейчас в школе Quest 1), без ПК. Базовая технология — WebXR; решение об APK и движке принимается по замеру и взвешенной рекомендации. **[частично]** WebXR работает; замер на школьном Quest 1 ожидается.
- Б2. Платформа кроссплатформенная. Задел на сетевые комнаты, удалённые уроки, совместную работу группы в одной комнате. **[в плане]**
- Б3. Школа может подключить локальный сервер (быстрые медиа, сеть, общие комнаты) и параллельно использовать интернет. Адрес сервера — список: сначала локальный, потом облако. **[в плане]**
- Б4. Обосновать закупку шлемов (грант): платформа даёт измеримый результат обучения, есть отчёт директора. **[в плане]**

**Обучение**
- Б5. Комнаты по предметам: математика, физика, химия, космос, биология, обществознание, логика, история России до 1991 года (без спорных и острых политических моментов), галерея. **[сделано]**
- Б6. Учётки учеников со сменой на старте, код входа у каждого, тесты по классам, отдельная страница учителя с прогрессом и рейтингом. Группа на уроке — примерно 5 учеников. **[сделано]**
- Б7. Конструктор тестов для учителей; встроенные тесты по уровням сложности для разных классов (1–4, 5–6, 7–8, 9–11). **[сделано]**
- Б8. Ядро с подключаемыми комнатами (уроки, тесты, игры). **[частично]** Контракт комнат есть; комнаты как данные (RoomSpec) в плане.
- Б26. Обучение интересное, познавательное и интерактивное: каждый предмет — отдельная комната с визуализацией (математика, геометрия, физика, химия, интересное о космосе), весело, а не скучно. **[частично]** Базовые комнаты есть, углубление и дизайн — в плане.
- Б27. Прогресс ученика — прохождение тестов на качество усвоения материала; материал и тесты делятся по классам; учитель видит прогресс и рейтинг. **[сделано]**
- Б28. На стартовом экране — смена учётки через последовательный фильтр с выпадающими списками «класс → ученик», без плиток всех учеников. **[сделано]**
- Б29. Рейтинг класса математически корректный: учитывает размер класса (байесовское среднее, чтобы у больших классов статистика не была хуже). **[сделано]**
- Б30. Времени на урок хватает группе из 5 учеников (таймер сеанса, минуты настраиваются). **[сделано]** Подтвердить на реальных уроках.
- Б36. Объекты в комнатах взаимодействуют друг с другом. **[в плане]**
- Б37. Удалённые уроки и лекции в VR с инструментарием учителя: демонстрации, видео, фото, текст, аудио. **[в плане]**

**Комнаты учителей и платформа**
- Б9. Учителя сами создают комнаты. Лучшие продвигаются по школам, учителя делятся опытом. **[в плане]**
- Б10. Система оценок комнат выявляет лучшие. **[в плане]**
- Б11. Модерация с участием учителей-экспертов, эксперты подключаются с первого дня. Режим выпуска настраивает суперадминистратор: «слово владельца после решения экспертов» или «автоматически после согласия экспертов». По умолчанию — слово владельца. **[в плане]**
- Б12. Лицензии комнат сейчас только свободные. Поле для платных остаётся в формате, но выключено. **[в плане]**
- Б13. Учитель может использовать свои загруженные материалы для отладки и сбора мнений, пока они не прошли модерацию; такие комнаты видны только автору и приглашённым и не публикуются. **[в плане]**
- Б14. Профили производительности: два, `lite` (Quest 1) и `standard` (Quest 2/3). **[в плане]**
- Б15. Монетизация закладывается: отчисления авторам пропорционально реальным школьникам, но проект тоже зарабатывает. Модель выбирается позже, поля и учёт использования закладываются сразу. **[в плане]**
- Б41. Администрирование учёток по цепочке: суперадминистратор — все учётки; директор — учителей своей школы; учитель — учеников своих классов. Поиск учёток последовательным фильтром «регион → школа → класс (к классу привязан учитель)» или по учителю; регион — признак школы для поиска. **[в плане]** Подробности — `docs/ROLES.md`, раздел 7.
- Б40. Иерархия сущностей: школа → директор и экспертный совет → учителя → классы → ученики; подробности и предложения по усилению — `docs/ROLES.md`. **[в плане]**

## В. Проверка правки по законам (перед каждым пушем)

1. Затронут ли только один модуль? Если несколько, есть ли проверки контрактов между ними (А1, А4)?
2. Что будет, если мой модуль упадёт? Остальное работает? (А3)
3. Старые данные читаются? Новые поля необязательны? (А5, А6)
4. Есть ли подтверждение у опасного действия? Есть ли отмена? (А9)
5. Права проверяются на сервере? Не нарушена иерархия? (А10, А17)
6. Нет ли секретов в публичных файлах? (А14)
7. Нет ли удаления без согласия? (А15)
8. Не противоречит ли правка требованиям раздела Б? Обновлён ли статус?
9. Обновлены `HANDOFF.md`, `CHECKLIST.md`, `sw.js` (версия, список файлов), проверки зелёные.

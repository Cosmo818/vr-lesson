# Протокол сети: кадры поз (версия pv = 1)

Источник — `PLAN-network.md` §3. Реализация: `js/netproto.js` (клиент) и `server/netproto.py` (сервер); одинаковые байты проверяет `tests/fixtures/net_frames.json` (`tests/run.js` и `tests/net_proto.py`). Пересборка фикстуры — `node tests/make_net_fixture.js`, только при намеренной смене формата (тогда `pv++`). Порядок байтов — little-endian.

## Кадр позы клиент → hub, 52 байта (тип 0x01)
| Смещение | Тип | Поле |
|---|---|---|
| 0 | u8 | `pv` |
| 1 | u8 | тип `0x01` |
| 2 | u16 | `seq` (по модулю 2¹⁶) |
| 4 | u32 | время клиента, мс (по модулю 2³²) |
| 8 | тело позы, 44 байта (ниже) | |

## Тело позы, 44 байта
| Смещение | Тип | Поле |
|---|---|---|
| 0 | u8 | флаги: b0 левая рука есть, b1 правая есть, b2 в VR, b3 откалиброван, b4 сидя, b5 в меню, b6 держит предмет, b7 нет трекинга |
| 1 | u8 | индексы самого большого компонента кватернионов (по 2 бита: голова, левая, правая) |
| 2 | 3×i16 | голова: позиция, мм |
| 8 | 3×i16 | голова: поворот («три меньших») |
| 14 | 3×i16 + 3×i16 | левая рука: позиция мм, поворот |
| 26 | 3×i16 + 3×i16 | правая рука |
| 38 | i16, i16 | физическая позиция головы x, z, мм (в общей рамке класса) |
| 42 | i16 | физическое направление взгляда, рад × 10⁴ |

Позиции — мм в i16, диапазон ±32,7 м: значения за границей обрезаются, `NaN` → 0. Кватернион: нормируется (нулевой и `NaN` → единичный), выбирается компонент с наибольшим модулем, весь кватернион домножается на −1, если он отрицательный (−q и q — один и тот же поворот); три остальных (по порядку x, y, z, w без выбранного) → i16 = c·32767·√2 (диапазон ±1/√2). Точность поворота ≈ 0,003 рад.

## Пачка hub → клиент (тип 0x81)
`[pv u8][0x81 u8][tick u16][srvTime u32][count u8]` — 9 байт, затем `count` записей по 46 байт: `[slot u8][ageQ u8 (возраст ×4 мс, ≤ 1020 мс)]` + тело позы (44 байта). Не более 255 записей. Уточнение к плану: в плане запись названа «42 Б» — на деле 44 байта тела (физическая поза занимает 6 байт); размер на человека 46 байт.

## Разбор
Кадр с неверной длиной, `pv` или типом отвергается (`null`/`None`), а не разбирается частично. Имён и идентификаторов в позе нет: номер места (`slot`) подставляет hub.

## Вход: билет (`server/hubticket.py`)
`b64url(payload) + '.' + b64url(HMAC-SHA256(k_ticket, payload)[:16])`; `k_ticket = HMAC(hubSecret,'ticket')`, `k_report = HMAC(hubSecret,'report')`.
payload: `{v:1, kid, aud, sid, k:'lesson'|'play', sch, cls, uid, r:'s'|'t'|'a', n, exp, j}`. Поле `k` добавлено к плану (§5.3): hub создаёт сессию в памяти по первому верному билету. `exp` — не раньше «сейчас» и не дальше 10 мин; `j` одноразовый (помнится до `exp`). Роль `v` (зритель трансляции) пока не пускается — шаг Н16.

## Управляющие сообщения (JSON, текстовые кадры)
Клиент → hub — не больше 2 КБ (иначе 4010), битый JSON или не объект — 1007. Первое сообщение — только `hello` (иначе 4001), срок 5 с от рукопожатия (ping-кадры срок не продлевают; иначе 4009).

| Клиент → hub | Ответ / рассылка |
|---|---|
| `hello {pv, ticket}` или `hello {pv, resume}` | `welcome {slot, resume, srv, tick, hz, hold, limits:{pose_hz,ctl,text}, sess:{id,kind,chat,mode,freeze,pointers}, roster:[{slot,name,role,col,room,away}]}`; другим — `roster+ {slot,name,role,col,room,away}` (новое место) или `roster~ {slot,name,role,room}` (возврат на место) |
| `p {c}` | `P {c, s}` — `s` — время hub, мс (то же, что `srvTime` в пачке) |
| `room {id}` (id `[A-Za-z0-9_]{1,24}`) | другим — `room {slot, id}`; позы — только внутри комнаты |
| `ev {k:'point', on, o:[x,y,z], d:[x,y,z], ci 0..6}` | той же комнате — `ev {k:'point', slot, on, o, d, ci}`; ученикам — если `sess.pointers` и нет `freeze` |
| `ev {k:'react', e 0..11}` | той же комнате — `ev {k:'react', slot, e}`; не чаще раза в 2 с |
| `ev {k:'rate', hz}` (5, 10, 15, 20) | — (частота пачек этому клиенту) |
| `ev {k:'gather', id?}` (id — комната урока, из кабинета: сбор у доски), `ev {k:'hall'}`, `ev {k:'freeze', on}`, `ev {k:'follow', on}`, `ev {k:'room', id}` | только `r:'t'`; всем — то же со `slot` ведущего; иначе `err {code:'role'}` |
| `ev {k:'kick', slot}` | только `r:'t'` и только ученика (`s`): ему 4012, всем `roster- {slot, why:'kick'}`; uid не пускается до закрытия сессии; удаление повторяется в отчёте, пока app.py не вернёт uid в `banned`; список `banned` от app.py полный — `session.unkick` снимает запрет в hub |
| `bye` | место освобождается сразу: всем `roster- {slot, why:'left'}` |
| `ev {k:'st', cal 0..1, off 0..1, near 0..2, vr 0..1, fps 0..240}` (шаг Н9) | учителю и наблюдателям (`r:'t'`/`'a'`) во всех комнатах — `ev {k:'st', slot, …}`; ученикам не идёт. Клиент шлёт при изменении (не чаще 2/с) и раз в 5 с. Поле не целое — сообщение молча отбрасывается |

Hub → клиент сам: `away {slot, on}` (нет поз > 3 с или обрыв), `roster- {slot, why:'gone'}` (место не вернули за 120 с), `sess {sess}` (настройки из кабинета), `err {code, msg}` (`unknown`, `role`, `kick`).

Пределы: позы ≤ 30/с (лишнее молча отбрасывается), управление — ведро 20 с пополнением 10/с, указка — отдельное ведро 12/с; отбрасывания подряд дольше 10 с — 4009. Медленный клиент (буфер отправки): > 32 КБ — пачка через такт, > 128 КБ — 5 Гц, > 512 КБ дольше 5 с или > 2 МБ — 4008 (место держится для `resume`).

Отбор в пачку: та же комната; 12 ближайших по виртуальному положению — каждый такт, остальные — каждый 4-й; учитель и физически ближе 3 м (оба откалиброваны, флаг b3) — всегда, **физически близкие — и из других комнат** (кольца безопасности, Н9). Кабинет учителя (`r:'t'`/`'a'`, ни одной своей позы) получает позы всех комнат — для плана класса.

Физическая поза (байты 38–43) при флаге b3 — в рамке класса после калибровки (`js/netsafe.js`), направление — угол `atan2(z,x)` взгляда; без b3 — в `local-floor` отправителя, hub и соседи её не используют. `sess` и `welcome.sess` несут `stations:[{id,x,z,yaw}]` (≤ 4, yaw — градусы направления A→B; в app.py — `clean_stations`, старые строки Н8 → в начале координат).

`resume` — 32 случайных байта (b64url), действует, пока место держится (120 с после обрыва), меняется при каждом входе. Второе подключение с тем же `uid` (в любой сессии) — старое закрывается 4014.

### Коды закрытия
4001 билет/resume плох, 4003 нет прав (hub без сессий), 4008 медленный, 4009 флуд или нет `hello`, 4010 сообщение больше 2 КБ, 4011 сессия закрыта, 4012 удалён учителем, 4013 версия `pv`, 4014 второе подключение, **4015 мест нет** (добавлен к плану), 1002/1007/1009 — нарушения WebSocket, 1011 внутренняя ошибка hub.

### Отчёт hub → app.py (шаг Н4)
Раз в 60 с, при закрытии и когда сессия опустела: `{sid, attend:[{uid,role,first,last,joins}], chat:[], kicked:[uid], final?, ended?}`, подпись `sign_report(k_report, тело)`. Ответ app.py: `{closed:[sid], banned:{sid:[uid]}, settings:{sid:{chat,mode,maxSeats,pointers}}}` — hub закрывает сессии (4011), удаляет (4012), рассылает `sess`. Позы, координаты и ходы в отчёт не идут.

## HTTP-интерфейс сервера (шаг Н4, `server/netapi.py`, всё под `config.json` → `net: true`, иначе 404)
Ответы — после фиксации транзакции. Секреты (`hubSecret`) только в `config.json` (0600); `python3 server/app.py hub-secret` создаёт (`--rotate` — заменяет), `net on|off` включает (без секрета не включится). Таблицы миграции v7: `room_sessions`, `room_attend`, `net_chat` (уникально по сессия+ts+uid), `broadcasts`, `hub_nodes` (последние две пока пусты).

| Запрос | Кто | Что |
|---|---|---|
| `POST /api/admin/session.open {class_id, room?, settings?}` | учитель этого класса, директор школы, выше (`class_in_scope`) | один открытый `lesson` на класс (409); при `settings.remote` — ответ содержит `code` (один раз, в базе хэш) |
| `session.close / settings / kick / unkick {id, …}`, `session.list {class_id?}`, `session.chat {id}` | те же | закрытие не удаляет; `kick` добавляет `uid` ученика в `banned` (≤ 200); `chat` пишет просмотр в журнал. Эксперт — 403, чужая школа/класс — 404 |
| `GET /api/session/live` (ключ шлема) | шлем школы | открытые сессии школы: `id, class_id, kind, room, created` |
| `POST /api/room/ticket {session_id, student_id, pin_hash}` (ключ шлема) | шлем | сервер сверяет: ученик активен, школа и класс, `pinHash` (`compare_digest`), не в `banned`; ученик без кода — только если `settings.noPin`; пауза по ученику после 5 ошибок (30 с, растёт вдвое до 15 мин — как у входа), общего лимита по IP нет (класс входит пачкой), лимит шлема 120 билетов/мин. На любую причину отказа — одинаковый 403 `denied` |
| `POST /api/room/ticket {session_id}` (Bearer) | учитель класса → `t`; директор и выше, эксперт школы → `a`; остальные 403 | uid в билете `u:<id пользователя>` |
| `POST /api/room/ticket {code, student_id, pin_hash}` | удалённый ученик | только `settings.remote`; 10 запросов/мин и пауза после ошибок по IP; ошибки кода ученика считаются отдельно от шлема (чужой с кодом урока не ставит на паузу ученика в классе) |
| `POST /api/play/join {class_id, student_id, pin_hash}` (ключ шлема) | шлем | класс должен иметь `playAllowed: true`; находит или открывает единственную `play`-сессию класса (чат `phrases`) и выдаёт билет. Окно времени школы — шаг Н12 |
| `POST /api/hub/report` | hub | тело ≤ 64 КБ, заголовок `X-Sig = HMAC-SHA256(k_report, тело)`, в теле `ts` (мс) — старше 5 мин отказ 400; последний отчёт (`final`) опустевшей **игровой** закрывает её (урок закрывает только учитель); идемпотентно (`first` — min, `last` — max, `joins` — max; чат по сессия+ts+uid); `kicked` → `banned`; ответ `{closed, banned, settings}` |
| `GET /api/hub/sessions` | hub | `X-Ts` (мс, ±60 с) и `X-Sig = HMAC(k_report, 'sessions:' + ts)`; открытые и закрытые за сутки |
Билет: `{aud: hubId||'center', sid, k, sch, cls, uid, r, n, exp, j}` (+`kid`, если задан `hubKid`); ответ `{ticket, exp, role, hubs:[{url, kind:'center'}], sess:{id, kind, room, chat, mode}}` — `url` берётся из `hubUrl` в `config.json` и приходит только с сервера (А14).
В журнал аудита: `session.open/close/settings/kick/unkick/ticket`, `session.chat.view`, `play.open`, `config.net`, `config.hubSecret` (без значения); отчёты hub пишутся как `cli` / `hub:center`.

Запуск hub против app.py: `python3 server/hub.py --config /data/config.json` (нужны `hubSecret`, `hubOrigins`; `hubAppUrl` — адрес app.py, по умолчанию отчёты пишутся только если задан `--report-file`). Раз в 60 с — отчёт, раз в 10 с — опрос закрытых сессий (`--report_s`, `--poll_s` для тестов).

### Остаточные риски (ревью Opus Н4, 28.10.2026)
- Сервер сверяет `pinHash`, а не сам код: шлем школы хранит хэши кодов своих учеников (так работает вход без сети), значит украденный ключ шлема даёт войти в урок за любого ученика этой школы. Это не шире, чем уже есть (тот же ключ пишет результаты за учеников); защита — отзыв шлема в кабинете.
- Отчёт hub можно повторить в течение 5 мин, если перехватить его во внутренней сети между hub и app.py; все действия отчёта монотонны, кроме `kicked` (повтор снова удалит ученика, которого учитель только что вернул). Канал hub↔app — только внутри Docker/localhost.
- Эксперт школы получает билет наблюдателя в любую сессию школы, включая игровую (так в плане §5.2).

# Протокол сети: кадры поз (версия pv = 1)

Источник — `PLAN-network.md` §3. Реализация: `js/netproto.js` (клиент) и `server/netproto.py` (сервер); одинаковые байты проверяет `tests/fixtures/net_frames.json` (`tests/run.js` и `tests/net_proto.py`). Пересборка фикстуры — `node tests/make_net_fixture.js`, только при намеренной смене формата (тогда `pv++`). Порядок байтов — little-endian.

## Кадр позы клиент → hub, 52 байта (тип 0x01)
| Смещение | Тип | Поле |
|---|---|---|
| 0 | u8 | `pv` |
| 1 | u8 | тип `0x01` |
| 2 | u16 | `seq` (по модулю 2¹⁶) |
| 4 | u32 | время клиента, мс (по модулю 2³²) |
| 8 | тело позы, 44 байта (ниже) | |

## Тело позы, 44 байта
| Смещение | Тип | Поле |
|---|---|---|
| 0 | u8 | флаги: b0 левая рука есть, b1 правая есть, b2 в VR, b3 откалиброван, b4 сидя, b5 в меню, b6 держит предмет, b7 нет трекинга |
| 1 | u8 | индексы самого большого компонента кватернионов (по 2 бита: голова, левая, правая) |
| 2 | 3×i16 | голова: позиция, мм |
| 8 | 3×i16 | голова: поворот («три меньших») |
| 14 | 3×i16 + 3×i16 | левая рука: позиция мм, поворот |
| 26 | 3×i16 + 3×i16 | правая рука |
| 38 | i16, i16 | физическая позиция головы x, z, мм (в общей рамке класса) |
| 42 | i16 | физическое направление взгляда, рад × 10⁴ |

Позиции — мм в i16, диапазон ±32,7 м: значения за границей обрезаются, `NaN` → 0. Кватернион: нормируется (нулевой и `NaN` → единичный), выбирается компонент с наибольшим модулем, весь кватернион домножается на −1, если он отрицательный (−q и q — один и тот же поворот); три остальных (по порядку x, y, z, w без выбранного) → i16 = c·32767·√2 (диапазон ±1/√2). Точность поворота ≈ 0,003 рад.

## Пачка hub → клиент (тип 0x81)
`[pv u8][0x81 u8][tick u16][srvTime u32][count u8]` — 9 байт, затем `count` записей по 46 байт: `[slot u8][ageQ u8 (возраст ×4 мс, ≤ 1020 мс)]` + тело позы (44 байта). Не более 255 записей. Уточнение к плану: в плане запись названа «42 Б» — на деле 44 байта тела (физическая поза занимает 6 байт); размер на человека 46 байт.

## Разбор
Кадр с неверной длиной, `pv` или типом отвергается (`null`/`None`), а не разбирается частично. Имён и идентификаторов в позе нет: номер места (`slot`) подставляет hub.

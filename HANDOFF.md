## Контракт комнаты
```js
VR.ROOMS.id = {
  title, hint, env:{floor,wall,trim,grid,open}, spawn:{x,z},
  build(E,S){},          // создать статику, панели, предметы; S — состояние комнаты
  targets(E,S){return[]},// объекты под лучом: {c:[x,y,z], r, id, sel(hand)}
  update(E,S,dt){}, draw(E,S,add){}, onGrab(E,S,b){}, onRelease(E,S,b,speed){},
  pick(E,S,h,hit){}      // необязательный: «держать» по панели без предмета на луче -> вернуть новое тело (E.addBody) или null; hit={t,kind:'panel',p,bi}
};
```
Опция панели `keepTex:true` — движок не перерисовывает её при наведении и нажатии (большие статичные панели). `E.labelTex(key,draw(ctx,128))` — кэш текстур-плашек 128x128 (до 160, иначе null). Стик Y при удержании предмета в VR двигает его вдоль руки (`off[14]`, −6…0; проверить в шлеме). Инструменты движка для комнат: `E.addPanel({w,h,pos,yaw,draw(c,p)})` (в `draw`: `p.text`, `p.button`, `p.area`), `E.addBody`, `E.addStatic`, `E.addTable`, `E.door`, `E.discover(subj,key,label)`, `E.toast`, `E.burst`, `E.beep/chime/fanfare`, `VR.makeQuiz(E,subj,pos,yaw)`.

Чтобы добавить комнату: 1) код по контракту в `rooms2.js` или новом файле; 2) предмет в `D.subjects` и `VR.ORDER`; 3) дверь в `DOORS` холла; 4) вопросы в `questions.js`; 5) новый файл — в `index.html` и `sw.js` (поднять версию кэша); 6) тест в `tests/run.js`.

## Данные (`VR.Store`)
Состояние: `{classes, students, results, disc, tests, feedback, deleted, settings}`. У ученика `classId` и `pinHash` (код входа, PBKDF2, соль `st:<id>`). Рейтинг классов — `Store.classStats()` (байесовское среднее, K=5). Ключ шлема может только добавлять учеников, но не менять существующих. Слияние: ученики, тесты и настройки — побеждает последняя правка (`updated`); результаты, открытия и отзывы — объединение; `deleted` — список удалённого; `settings.resetAt` — граница очистки результатов. Ключ шлема не может менять тесты, настройки и удалять. Логика одинакова в `store.js` (merge) и `server/app.py` (merge_in) — правки вносить в оба места.
Схема v3 (22.10.2026): у классов и учеников `school` (по умолчанию `school-default`), `year` (учебный год, с августа), `status` (`active`/`archived`). «Удалить» в кабинете учителя = «В архив», вкладка «Архив» с «Вернуть» (проверка дубля класса, предупреждение, если класс ученика в архиве). Старый клиент без новых полей не «воскрешает» архивные записи (перенос полей `carry` в `schema.js`, `fill_v3` в `app.py`). Ключ шлема всегда создаёт ученика активным, в школе по умолчанию, без архивного класса, год считает сервер. Миграция сервера v2→v3 — одна транзакция, копия базы `vrlesson.db.bak-v2-*` рядом с базой, `PRAGMA user_version=3`. Роли школа/директор — в плане (`docs/ROLES.md`).
Схема v4 (22.10.2026, шаги 1–3 плана): миграция v3→v4 (`migrate_v4`) только добавляет — таблицы `schools`, `users`, `user_roles`, `sessions`, `invites`, `login_fail`, `audit_log` (пока пустые, кроме строки `school-default`), колонку `classes.teacherId` и индексы; копия базы `vrlesson.db.bak-v3-*`, `user_version=4`. Откат на старый код безопасен: он открывает базу v4 (но понижает `user_version` до 3, новый код при старте снова делает копию и поднимает до 4) — это проверено в `tests/run.js` замороженной копией `tests/fixtures/server_v3.py`. `teacherId` класса: сервер хранит и отдаёт его, но присланное значение игнорирует (`fill_v4` в `server/app.py`, `carry`/`adoptTeacher` в `js/schema.js`); ставится только будущим действием «передать класс» (шаг 7). Видимый код ученика (Б42): поле `pinView` (4–8 цифр) в записи ученика, ставится вместе с `pinHash` (`Store.setStudentPin`); сервер отдаёт его только ключу учителя (`state(c, hide_pins)`), от шлема не принимает; при записи старым клиентом сохраняется, пока хэш кода тот же. Глазик и печать — `teacher.html` (`codeCell`, `printCodes`). Журнал аудита: `audit()` в `merge_in`, пишутся только реальные изменения (создание ученика/класса, смена кода ученика — без значения, архив/возврат, удаление, имена изменённых настроек), исполнитель `legacy-teacher` (ключ учителя) или `device`; в `detail` нет секретов, объём до 2 КБ, записи не удаляются.

## Проверка
- `node tests/run.js` — около 150 проверок на имитации шлема, вместе с живым сервером (нужен python3). Первым делом запускает `tests/laws.js` (автопроверка законов из `docs/LAWS.md`: файлы `sw.js`, секреты в публичных файлах, слои, порядок вопросов по `tests/laws.baseline.json`, контракты). Новый вопрос в конец `js/questions.js` — обновить базу: `node tests/laws.js --update-baseline`.
- `python3 tests/e2e.py` — проверка в настоящем браузере: навигация, перезагрузка, вход учителя.
- `python3 tests/e2e_chem.py` — комната «Химия» в браузере: рендер панелей (`p.over` пуст), картинки `shots/chem_*.png`, хват из таблицы клавишей E.
- `python3 tests/shots.py . shots` — скриншоты в Chromium (Playwright).

## Известные ограничения
- Учётки учеников — имя и класс, без почты. Регистрация по почте и согласия по 152-ФЗ — в плане развития.
- Свой движок без библиотек — каркас. Для текстур, моделей и сетевой игры план — переход на Babylon.js или three.js (см. план развития).
- Сервер: один процесс, SQLite, без rate limit, кроме задержки на неверный ключ.

Сбои и их решения — в `CHECKLIST.md`.

# Чек-лист: найденные сбои и как их не повторять

- Python на Windows: строка `Python` без версии в ответ на `python …` — это заглушка Microsoft Store. Ставить через `winget install Python.Python.3.12`.
- `adb` не найден: нужен пакет Google Platform Tools (`winget install Google.PlatformTools`) и перезапуск PowerShell.
- GitHub Pages: загружать файлы, а не zip, и класть `index.html` в корень репозитория.
- WebXR и офлайн-кэш работают только по `https://` или `localhost`. Сервер на Pi тоже должен быть доступен по HTTPS, иначе браузер заблокирует запросы со страницы GitHub Pages.
- После добавления новых файлов в проект добавить их в `sw.js` (список FILES) и увеличить версию кэша.
- Порядок вопросов в `js/questions.js` не менять: id вопросов зависят от позиции, иначе статистика «сложных вопросов» перепутается.
- В облачной сессии Claude: npm-реестр недоступен (поэтому движок без библиотек); пуш в репозиторий требует подключить его к сессии.
- Режим экрана: клавиши и мышь «залипали», если отпустить их вне окна, переключиться на другое окно или вызвать системное меню. Теперь при потере фокуса, уходе со вкладки, `pointercancel` и `lostpointercapture` ввод сбрасывается. Новые обработчики ввода добавлять туда же (`releaseAll` в engine.js).
- Pi (OpenWrt): `git clone https://…` падает с «git: 'remote-https' is not a git command» — нет пакета `git-http` (`apk add git-http`; на старых OpenWrt `opkg install git-http`). Если `docker run -v` запустить до клонирования, Docker сам создаёт пустые папки, поэтому код лежит в `/opt/vr-lesson-app`. Перед `docker run` проверить, что `/opt/vr-lesson-app/server/app.py` существует.
- Ключ сервера: при копировании из keys.json легко захватить кавычки или запятую, тогда сервер отвечает 401. Теперь страница сама очищает ключ от кавычек и пробелов, а поле можно показать галочкой «показать».
- CSS: класс с `display:flex` перебивает атрибут `hidden` — форма «Новый ученик» была видна всегда. В style.css добавлено `[hidden]{display:none!important}`.
- Страница учителя «зависала» после возврата из справки или перезагрузки: автовход по сохранённой сессии вызывался раньше, чем объявлена переменная `ed` (`let`) → ошибка «Cannot access before initialization», и обработчики кнопок не навешивались. Правило: код, который запускает отрисовку при загрузке, ставить в самый конец скрипта. Проверка: `python3 tests/e2e.py` (навигация «Справка → Назад», перезагрузка, вход).
- Стартовая страница при возврате кнопкой «Назад» из кэша браузера перезагружается (`pageshow` + `persisted`), чтобы не остаться с неживым WebGL.
- Безопасность: сессия учителя живёт 15 минут без действий и закрывается при переходе к ученикам (кнопка «Выйти к ученикам», открытие стартовой страницы), иначе ученик в шлеме мог зайти «Назад» в страницу учителя без пароля. В шлеме на сервере использовать только ключ шлема: он не может менять тесты, настройки и удалять данные, а сервер не даёт перезаписать уже сохранённые результаты.
- Шлем дома не подключался к серверу («Failed to fetch»): мешал VPN на роутере. Решение: шлему прямая маршрутизация без VPN. Перед школой проверить адрес `/api/health` с телефона через мобильный интернет без VPN; если не открывается — переходить на прямой доступ по белому IP (Caddy + домен).
- Вход ученика: код хранится только хэшем; ключ шлема на сервере может лишь добавлять учеников, но не менять существующих (иначе можно было бы подменить код другого ученика). После 5 неверных попыток — пауза 30 с. Новые коды показываются учителю один раз — при смене класса список сбрасывается.
- В репозиторий случайно попал `server/__pycache__/app.cpython-313.pyc` (кэш Python после проверки синтаксиса). Добавлен `.gitignore`; сам файл убрать из репозитория только с согласия владельца.
- В шлеме пропали сервер и ключ после обновления (код хранения не менялся). Обычно это браузер Quest очищает данные сайта: после обновления системы, при нехватке места или очистке истории. Теперь сайт просит постоянное хранилище (`navigator.storage.persist`). Если всё же пропало — заново ввести адрес и ключ шлема; ученики и результаты вернутся с сервера, потеряется только то, что не успело отправиться.
- VPS vrklass.ru обновляется сам: cron раз в 2 минуты запускает `deploy/autoupdate.sh` (git fetch + fast-forward, перезапуск API при изменении `server/`, reload Caddy при изменении Caddyfile). Журнал: `/var/log/vr-autoupdate.log`. Поэтому в `main` пушить только после зелёных проверок; история main — только вперёд (без force-push), иначе автообновление остановится.
- Страница учителя: после «Подключить» навсегда висела «Связь…». Причина: в `renderRating` локальная переменная `cls` (список классов) перекрыла функцию `cls()` (цвет оценки) → ошибка «cls is not a function», как только у учеников есть результаты; `renderAll` обрывался и не доходил до статуса сервера. На пустых тестовых данных не проявлялось. Исправлено: переименование, каждая вкладка рисуется в своём try/catch, статус сервера рисуется первым. Правила: не называть локальные переменные как общие функции; e2e-тест гоняет страницу на данных старого формата с результатами и проверяет, что статус меняется на «Синхронизировано» или «Ошибка».
- Python 3.13: sqlite3 не открывает транзакцию перед DDL (ALTER TABLE фиксируется сразу). Миграции сервера делать в явной транзакции (BEGIN IMMEDIATE … COMMIT/ROLLBACK), перед миграцией — копия базы (найдено ревью шага 3, 22.10.2026).
- e2e: поля адреса сервера лежат на вкладке «Данные»; после работы на другой вкладке тест должен открыть её (иначе fill ждёт невидимый элемент). Возврат из архива: проверять дубль класса (параллель+буква среди активных), иначе получаются два активных «7Г».
- Карта кода (ветка graph): в неглубоком клоне `git fetch origin graph` не создаёт origin/graph, нужен `git fetch origin graph:refs/remotes/origin/graph`. В начале каждой задачи сначала `wiki/index.md` из ветки graph, и только потом чтение больших модулей; в сессии 21–22.10.2026 это правило было пропущено (замечание владельца).

# Чек-лист: найденные сбои и как их не повторять

- Python на Windows: строка `Python` без версии в ответ на `python …` — это заглушка Microsoft Store. Ставить через `winget install Python.Python.3.12`.
- `adb` не найден: нужен пакет Google Platform Tools (`winget install Google.PlatformTools`) и перезапуск PowerShell.
- GitHub Pages: загружать файлы, а не zip, и класть `index.html` в корень репозитория.
- WebXR и офлайн-кэш работают только по `https://` или `localhost`. Сервер на Pi тоже должен быть доступен по HTTPS, иначе браузер заблокирует запросы со страницы GitHub Pages.
- После добавления новых файлов в проект добавить их в `sw.js` (список FILES) и увеличить версию кэша.
- Порядок вопросов в `js/questions.js` не менять: id вопросов зависят от позиции, иначе статистика «сложных вопросов» перепутается.
- В облачной сессии Claude: npm-реестр недоступен (поэтому движок без библиотек); пуш в репозиторий требует подключить его к сессии.
- Режим экрана: клавиши и мышь «залипали», если отпустить их вне окна, переключиться на другое окно или вызвать системное меню. Теперь при потере фокуса, уходе со вкладки, `pointercancel` и `lostpointercapture` ввод сбрасывается. Новые обработчики ввода добавлять туда же (`releaseAll` в engine.js).
- Pi (OpenWrt): `git clone https://…` падает с «git: 'remote-https' is not a git command» — нет пакета `git-http` (`apk add git-http`; на старых OpenWrt `opkg install git-http`). Если `docker run -v` запустить до клонирования, Docker сам создаёт пустые папки, поэтому код лежит в `/opt/vr-lesson-app`. Перед `docker run` проверить, что `/opt/vr-lesson-app/server/app.py` существует.
- Ключ сервера: при копировании из keys.json легко захватить кавычки или запятую, тогда сервер отвечает 401. Теперь страница сама очищает ключ от кавычек и пробелов, а поле можно показать галочкой «показать».
- CSS: класс с `display:flex` перебивает атрибут `hidden` — форма «Новый ученик» была видна всегда. В style.css добавлено `[hidden]{display:none!important}`.
- Страница учителя «зависала» после возврата из справки или перезагрузки: автовход по сохранённой сессии вызывался раньше, чем объявлена переменная `ed` (`let`) → ошибка «Cannot access before initialization», и обработчики кнопок не навешивались. Правило: код, который запускает отрисовку при загрузке, ставить в самый конец скрипта. Проверка: `python3 tests/e2e.py` (навигация «Справка → Назад», перезагрузка, вход).
- Стартовая страница при возврате кнопкой «Назад» из кэша браузера перезагружается (`pageshow` + `persisted`), чтобы не остаться с неживым WebGL.
- Безопасность: сессия учителя живёт 15 минут без действий и закрывается при переходе к ученикам (кнопка «Выйти к ученикам», открытие стартовой страницы), иначе ученик в шлеме мог зайти «Назад» в страницу учителя без пароля. В шлеме на сервере использовать только ключ шлема: он не может менять тесты, настройки и удалять данные, а сервер не даёт перезаписать уже сохранённые результаты.
- Шлем дома не подключался к серверу («Failed to fetch»): мешал VPN на роутере. Решение: шлему прямая маршрутизация без VPN. Перед школой проверить адрес `/api/health` с телефона через мобильный интернет без VPN; если не открывается — переходить на прямой доступ по белому IP (Caddy + домен).
- Вход ученика: код хранится только хэшем; ключ шлема на сервере может лишь добавлять учеников, но не менять существующих (иначе можно было бы подменить код другого ученика). После 5 неверных попыток — пауза 30 с. Новые коды показываются учителю один раз — при смене класса список сбрасывается.
- В репозиторий случайно попал `server/__pycache__/app.cpython-313.pyc` (кэш Python после проверки синтаксиса). Добавлен `.gitignore`; сам файл убрать из репозитория только с согласия владельца.
- В шлеме пропали сервер и ключ после обновления (код хранения не менялся). Обычно это браузер Quest очищает данные сайта: после обновления системы, при нехватке места или очистке истории. Теперь сайт просит постоянное хранилище (`navigator.storage.persist`). Если всё же пропало — заново ввести адрес и ключ шлема; ученики и результаты вернутся с сервера, потеряется только то, что не успело отправиться.
- VPS vrklass.ru обновляется сам: cron раз в 2 минуты запускает `deploy/autoupdate.sh` (git fetch + fast-forward, перезапуск API при изменении `server/`, reload Caddy при изменении Caddyfile). Журнал: `/var/log/vr-autoupdate.log`. Поэтому в `main` пушить только после зелёных проверок; история main — только вперёд (без force-push), иначе автообновление остановится.
- Страница учителя: после «Подключить» навсегда висела «Связь…». Причина: в `renderRating` локальная переменная `cls` (список классов) перекрыла функцию `cls()` (цвет оценки) → ошибка «cls is not a function», как только у учеников есть результаты; `renderAll` обрывался и не доходил до статуса сервера. На пустых тестовых данных не проявлялось. Исправлено: переименование, каждая вкладка рисуется в своём try/catch, статус сервера рисуется первым. Правила: не называть локальные переменные как общие функции; e2e-тест гоняет страницу на данных старого формата с результатами и проверяет, что статус меняется на «Синхронизировано» или «Ошибка».
- Python 3.13: sqlite3 не открывает транзакцию перед DDL (ALTER TABLE фиксируется сразу). Миграции сервера делать в явной транзакции (BEGIN IMMEDIATE … COMMIT/ROLLBACK), перед миграцией — копия базы (найдено ревью шага 3, 22.10.2026).
- e2e: поля адреса сервера лежат на вкладке «Данные»; после работы на другой вкладке тест должен открыть её (иначе fill ждёт невидимый элемент). Возврат из архива: проверять дубль класса (параллель+буква среди активных), иначе получаются два активных «7Г».
- Карта кода (ветка graph): в неглубоком клоне `git fetch origin graph` не создаёт origin/graph, нужен `git fetch origin graph:refs/remotes/origin/graph`. В начале каждой задачи сначала `wiki/index.md` из ветки graph, и только потом чтение больших модулей; в сессии 21–22.10.2026 это правило было пропущено (замечание владельца).
- Поле пароля учителя на телефоне показывало только цифровую клавиатуру: у input остался inputmode="numeric" от старого цифрового PIN, и учитель с буквенным паролем не мог войти (22.10.2026). Правило: поля паролей взрослых ролей — inputmode="text"; цифровой inputmode только для кода входа ученика. Проверка есть в e2e.
- Миграции сервера (шаги 1–3 плана учёток, 22.10.2026): `migrate_v3` при каждом старте ставила `user_version = SCHEMA` и понизила бы версию базы v4; теперь каждая миграция повышает версию только если она ниже своей (`user_version = 3` / `4`), порядок вызова v3 → v4. Прежний код (v3) на базе v4 всё равно ставит 3: новый код при следующем старте снова делает копию `bak-v3` и поднимает до 4 — так и задумано, данные не теряются (тест «откат» в `run.js`).
- Слияние классов на сервере: `INSERT OR REPLACE INTO classes` сбрасывает колонки, которых нет в списке, поэтому `teacherId` пишется явно из `fill_v4` (из прежней записи сервера); присланное значение игнорируется. Если добавляешь новую колонку в `classes`/`students`, добавь её и в этот INSERT, иначе она обнулится при первой правке.
- Любая синхронизация учителя чистит результаты старше `settings.resetAt` — в тестах «данные до и после» сравнивать до первой синхронизации, иначе разница в числе результатов не ошибка миграции.
- Журнал аудита: писать только при реальном изменении записи (иначе каждая синхронизация шлёт одни и те же данные и дублирует строки), в `detail` — имена и факты, никогда значения кодов, хэшей, ключей. Проверка в `run.js` ищет хэши и ключи по всей таблице.
- Кабинет учителя: `document.querySelector('tr[data-id=…]')` находит строку из другой вкладки (рейтинг тоже с `data-id`), и глазик «не работал». Искать строки внутри своей карточки (`$('cCard').querySelector`). В e2e есть проверка глазика после перезагрузки (22.10.2026).
- Печать на телефоне: `window.open` для листа блокируется, поэтому лист кодов строится на самой странице (`#psheet`) и показывается только в `@media print`; в e2e печать проверяется подменой `window.print` и `emulate_media('print')`. Локальные переменные в teacher.html не называть как общие функции (`rows`) — это проверяет `tests/laws.js`.
- Видимый код ученика (`pinView`, Б42): только в записи ученика на сервере и у учителя; `state(c, hide_pins=True)` для ключа шлема, шлем не пишет его при создании. Любой новый ответ сервера с учениками должен проходить через `state`, иначе код утечёт шлему (тест «pinView» в `run.js`).

- Новая комната с 9-й кнопкой в холле/меню: проверять раскладку (меню в 5 рядов сдвинуло «Закрыть/Отзыв» вниз) и счётчики кнопок в tests/run.js; панели с текстом — смотреть скриншотом (перекрытие подписей при переносе строк).

- Ответ клиенту нельзя отправлять внутри `with db() as c:` — соединение фиксирует транзакцию при выходе из блока, и клиент (или тест) может прийти за токеном/данными раньше фиксации. Собрать ответ внутри, отправить после блока (вход и сессии, 22.10.2026).
- Консольный ввод пароля: `getpass` на не-терминале пишет предупреждение в stderr, но читает stdin — так тестируются команды суперадмина.

- Все скрипты teacher.html должны быть и в index.html в том же порядке (закон про порядок скриптов): teacher-only файл (js/builder.js) подключён и в index.html, он безвреден без своей разметки. Движок читает `env`/`spawn`/`hint` комнаты ДО `build`, поэтому у комнат из данных это геттеры, а не поля, выставляемые в build.
- Редактор не должен ломать ввод перерисовкой: правка полей меняет данные и холст, но не пересобирает форму (фокус терялся бы); полная перерисовка — только при смене выбранного блока.

- Админ-действие со сменой директора проверяет пароль ДО проверки роли: отказ учителю без пароля не попадает в журнал; в тестах пароль передаётся всегда. `urllib.parse.parse_qs` не имеет `max_len` (падение на GET /api/options) — резать строку запроса вручную; код школы вида `s-xx…` не короче 2 знаков после `s-` (22.10.2026).

- Комната в окне (iframe) внутри редактора делит sessionStorage с кабинетом учителя: `index.html` при загрузке стирал `vrl.teacher`, и учитель выходил из кабинета через 20 с. Стирать только в верхнем окне (`window.self===window.top`). Режим «Править в VR» использует отдельный флаг `vrl.editor` (60 мин, стирается при выходе из редактора и в конце сеанса ученика); `sessionStorage` у каждой вкладки свой, поэтому в тестах вторая вкладка — того же контекста браузера (22.10.2026).

- 22.10.2026 · страница admin.js написала `'/api/auth/me'` напрямую — закон А2 (сеть только в store.js) поймал. Правило: новый запрос к API — сначала метод в `Store`, страница зовёт метод.
- 22.10.2026 · сервер отвечал 413 на большой файл, не читая тело — клиент видел обрыв связи, а не сообщение. Правило: при отказе по размеру дочитывать и выбрасывать тело (до MAX_BODY), потом отвечать.
- 22.10.2026 · в тестах логин короче 3 знаков и кириллица в адресе (имя файла) ломали запросы. Правило: имя в URL — всегда через quote/encodeURIComponent.
- 22.10.2026 · при проверке мыши в безголовом браузере: «сырой» захват (unadjustedMovement) даёт pointerlockerror до обычного — это не отказ, нельзя сразу включать запасной режим. Правило: ошибку засчитывать только после попытки обычного захвата; синтетические mousemove от Playwright несут скачки ±600 px — тестировать через MouseEvent с movementX.
- 22.10.2026 · коммит молча не состоялся: в цепочке `&&` стояло `grep -c …`, а он возвращает код 1 при нуле совпадений, и всё после него не выполнилось. Правило: подсчёты `grep -c` и сравнения не вставлять в цепочки `&&`; перед пушем отдельной командой `git log -1` и `git status`.
- 22.10.2026 · сервер проверял поле `v` у комнаты, а клиент хранит `schema`; тест на синтетических данных этого не заметил. Правило: тест публикации — на комнате, собранной настоящим клиентом (`tests/e2e_open.py`). Там же: роль специалиста привязана к школе, пустая школа не годится.
- 22.10.2026 · планировщик SQLite выбрал индекс по `closed` вместо индекса по `sid` и просматривал 720 000 строк (4 с вместо 0,2 с). Правило: условие по малоселективной колонке в запросе по списку id писать как `+closed = 0`; новые запросы проверять замером на большой базе (скрипт замера — в выводе сессии, шаблон в tests/open.py).
- 22.10.2026 · две страницы входа (кабинет и админка) путали: код приглашения принимала только админка, учителя отправляли в кабинет без поля кода; старое окно с кодом могло остаться под новым. Правило: вход один (Б57), одно окно диалога за раз, в заголовке окна кода — роль и школа.
- 22.10.2026 · панель «Обучение» в холле стояла на x=-3.9 и перекрывала дверь информатики (x=-4.2, ширина двери ±0,7). Правило: новую панель на стене холла ставить, сверив занятые отрезки по x: дверь info −4.9…−3.5, тесты учителя −1…1, комнаты учителя 2.9…4.9, обучение −3.15…−1.45.

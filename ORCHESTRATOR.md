# Оркестратор VR-урока

Схема работы для большого проекта (VR-портал: разработка + учебный контент). Живёт внутри Claude, на подписке, без API. Цель — самая дешёвая модель, которая справляется с задачей, и чистый контекст основного чата.

## Запуск

Субагенты запускаются только по слову Айрата: «через оркестратор» или имя роли. Без этого Claude работает сам. Мелочи (правка в 1–2 файлах, ответ на вопрос) оркестратор не нужен.

## Роли и модели

Описания ролей — `.claude/agents/*.md`. Если роль не подхватилась, запускать `general-purpose` с нужной моделью и текстом роли.

| Роль | Модель | Что делает | Что возвращает |
|---|---|---|---|
| scout | Haiku | Ищет по коду (grep), читает куски, собирает факты | выжимка до 15 строк с путями и номерами строк |
| architect | Opus | План, архитектура, безопасность, слияние данных, решения с компромиссами | пронумерованный план в `PLAN.md` |
| coder | Sonnet | Реализует готовый шаг плана, пишет тесты | список изменённых файлов, результат проверок |
| content | Sonnet | Вопросы, тексты уроков по классам | черновик в файл, не в чат |
| factcheck | Sonnet | Проверяет факты учебного контента по источникам | таблица «утверждение — источник — ок/нет» |
| reviewer | Sonnet (Opus для безопасности и данных) | Ревью перед пушем | список замечаний по важности |

## Маршрутизация

| Тип задачи | Кто |
|---|---|
| Найти, где что лежит; сколько чего | scout |
| Новая функция, комната, модуль | architect → coder → reviewer |
| Правка по готовому плану, баг с понятной причиной | coder |
| Баг с неясной причиной, вся система | architect, потом coder |
| Слияние данных, ключи, права, сервер | architect и reviewer (оба Opus) |
| Новые вопросы и уроки | content → factcheck |
| Переименования, форматирование, рутина | scout или coder, минимальный объём |

## Конвейер задачи

1. Оценка: лёгкая (сам), средняя (coder), тяжёлая (полный конвейер). Айрату — одна строка.
2. Тяжёлая: architect пишет план в `PLAN.md`. Айрат подтверждает до исполнения.
3. scout собирает контекст под шаг (пути и строки), чтобы coder не читал лишнее.
4. coder делает один шаг плана за запуск. Тесты запускает основной чат (`node tests/run.js`, `python3 tests/e2e.py`).
5. reviewer смотрит изменения до пуша.
6. Пуш — только основным чатом по скиллу `vr-lesson-push`. Агенты не пушат.

## Правила экономии

- Агенту давать точные пути и нужные разделы, не «посмотри проект».
- Просить короткий ответ (лимит строк) и результат класть в файл.
- Независимые шаги запускать параллельно, но не больше 3 агентов сразу. Клон и пуш — по одному.
- Не запускать агента на задачу меньше трёх файлов: накладные расходы выше выгоды.
- Новый чат на каждую задачу; в конце обновлять «Статус» в HANDOFF.md и `PLAN.md`.
- Opus — только планы, архитектура, безопасность. Исполнение не на Opus.

## Контент

- Уровни вопросов a/b/c/d = 1–4/5–6/7–8/9–11 классы; новые вопросы только в конец `js/questions.js`.
- Любой учебный факт проходит factcheck до попадания в сайт.
- Черновики контента — в `content/`, не в `js/`, пока не проверены.

## Границы

- Агенты ничего не удаляют, не трогают `keys.json` и данные учеников, не пишут ключи в файлы.
- Оркестрация работает, пока открыт чат. Работа по расписанию и без Айрата потребует отдельного сервиса (например, n8n с API-ключом), это позже.

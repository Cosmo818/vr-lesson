# PLAN-anchors — якорение класса: метки на стенах, касание, постоянные якоря, камера Quest 3

Цель — каждый шлем знает своё место в **системе класса** (общие координаты помещения), чтобы кольца безопасности (Н9), аватары и «Все ко мне» совпадали с настоящими людьми. Шлемы: **Quest 1 и 2** — основной парк; **Quest 3** — по возможности **автоматически, без действий ученика**, по меткам через камеру. Сейчас есть калибровка по станции касанием (`js/netsafe.js`: `calibSolve`, `holdCheck`, `toClass/fromClass`, объект `cal{r,ax,az,ox,oz}`), её и развиваем.

## 0. Решения и принципы

1. **Один физический набор меток для всех способов.** Лист A4 на стене: квадратный маркер AprilTag 36h11 (18 см), крупный номер и **крестик-цель для касания** в центре. Quest 1/2 — касаются крестика контроллером, Quest 3 — видит маркер камерой. Набор печатается с сайта (SVG → печать), без внешних сервисов.
2. **Все способы дают один и тот же `cal`** (поворот и сдвиг «пол шлема → класс»). Остальной код (`netsafe`, `netplay`, `netlead`) не знает, откуда взялся `cal`.
3. **Уровни, от автоматического к ручному**, у каждого — доверие и возраст:
   - **У1 — камера по меткам** (Quest 3, если браузер даёт кадры, см. К0): без действий, постоянно поправляет.
   - **У2 — постоянный якорь** (Quest 2/3, WebXR `anchors` + постоянный номер): после первой калибровки шлем в этом классе узнаёт место сам при каждом входе; якорь **не сбивается при «Перецентровке»** (кнопка Oculus), в отличие от `local-floor`.
   - **У3 — плоскости комнаты** (Quest 2/3 со сканом комнаты, `plane-detection`): стены и углы — проверка и запасной путь; сами по себе неоднозначны (прямоугольник симметричен), поэтому только вместе с У1/У2/У4.
   - **У4 — касание двух меток** (все шлемы, включая Quest 1): 5–10 секунд, точность 1–3 см. Опорный способ и «эталон» при первой разметке.
4. **Безопасность важнее удобства.** Кольца и «на своём месте» включаются только при `cal` с доверием «высокое»: У4 свежее, У1 с ≥ 2 метками, У2 подтверждённый (У1/У3 согласны в пределах 5 см / 2°). Расхождение источников > 10 см или > 3° — `cal` снимается, табличка «Откалибруйся у метки», кольца гаснут (как сейчас `lose()`).
5. **Камера — только на шлеме и только числа.** Кадр обрабатывается в памяти (Worker), наружу выходят номер метки и её положение; кадры не сохраняются, не рисуются в журнал и не уходят в сеть. Разрешение на камеру даёт учитель один раз при настройке шлема школы; у ученика ничего не спрашиваем. Без отдельного решения владельца камера выключена (флаг `camAnchors`, закон А7). Это ПДн детей — ревью Opus обязательно.
6. Совместимость (А6): шлем без новых функций работает как сейчас (станция касанием). Ничего не удаляется (А15).

## 1. Данные

- **Помещение** (кабинет, не класс учеников — в одном кабинете учатся разные классы): сервер, таблица `places(id, school_id, name, size_x, size_z, markers JSON, walls JSON, updated, updated_by)`; `markers=[{n, x, y, z, yaw}]` — центр крестика в системе класса (м), `yaw` — нормаль стены; `walls` — отпечаток стен из У3 (для проверки). Права — как у комнат урока: учитель своей школы, директор+. Урок (`session`) получает `place_id`; станции Н9 остаются (места учеников) и задаются в той же системе.
- **На шлеме:** `vrl.anchor.<place_id>` = `{uuid, cal, t, src}` в `localStorage` (номер постоянного якоря + `cal`, посчитанный относительно якоря). Ключа ученика тут нет — это свойство шлема, а не человека. Лимит Quest — 8 постоянных якорей на сайт: держим ≤ 6 помещений, старые вытесняем по давности **с подтверждением учителя** (А15).

## 2. Шаги

### К0. Разведка на настоящих шлемах (Айрат, 10 минут) — до любого кода
`tools/xrprobe.html` (уже есть): кнопки «VR-сеанс», «AR-сеанс», «Камера» → отчёт: включённые функции (`anchors`, `plane-detection`, `mesh-detection`, `camera-access`), есть ли постоянные якоря, метки плоскостей (`wall/floor/door/…`), даёт ли `getUserMedia` камеру шлема и работает ли она во время VR. Прогнать на Quest 2 и Quest 3 (Quest 1 — если под рукой). **От результата зависят У1–У3**; без К0 их не начинать.

### К1. Помещение и метки (сервер + кабинет) — ревью Opus обязательно
`server/places.py` (миграция v11 по образцу `studev.migrate_v9`, копия базы до транзакции, флаг `places`), API `place.list|get|save|archive`; в кабинете учителя — вкладка «Кабинеты»: имя, размер, список меток. Генератор листов меток `place-print.html` (AprilTag 36h11 — таблица кодов в `js/tag36h11.js`, рисование SVG, номер, крестик, подпись «верх»). Проверки: права (чужая школа — 403), миграция повторяема, старые клиенты не ломаются.

### К2. Разметка кабинета учителем в шлеме (все шлемы)
Учитель ставит листы на стены (высота крестика 1,2–1,5 м, расстояние между соседними ≥ 1,5 м, минимум 4 на кабинет, на разных стенах). В шлеме: «Разметить кабинет» → касается метки 1 и метки 2 (они задают оси: 1 — начало, 1→2 — ось X), затем по очереди остальных; координаты считаются из позы контроллера (среднее за 1 с удержания, разброс < 1 см — `holdCheck`). Если У3 доступен — заодно снимается отпечаток стен. Сохранение → `place.save`. Проверка расстояний «по рулетке» не нужна; повторная разметка — версия `updated`.

### К3. Касание двух меток вместо станции (все шлемы) — расширение `netsafe`
`calibSolve` уже решает задачу по двум точкам; станции заменяются любыми двумя метками помещения: ученик подходит к ближайшей паре (подсказка стрелкой), касается, `cal` готов. Проверка расстояния между касаниями против `markers` (± 5 см) ловит «не та метка». Чистые функции — в `VR.netsafe._pure`, проверки в `tests/netsafe.js`.

### К4. Постоянный якорь (Quest 2/3, если К0 подтвердил)
`engine.js`: `requestSession('immersive-vr', {requiredFeatures:['local-floor'], optionalFeatures:['anchors', 'plane-detection']})` — **опционально**, сеанс открывается и без них (Quest 1). После любой успешной калибровки (У4/У1) — `createAnchor` в точке метки 1 → `requestPersistentHandle()` → `vrl.anchor.<place>`; `cal` хранится относительно якоря. При входе: `restorePersistentAnchor(uuid)` → поза якоря → `cal` за ~1–3 с, без действий. Якорь не найден (другая комната, сброс карты) → обычный путь К3. Хук `E.hooks.onRefReset` (перецентровка) → `cal` пересчитывается от якоря, а не теряется. Доверие «высокое» — после подтверждения У1 или У3, иначе «среднее» (кольца есть, но пауза «Я на месте» как сейчас).

### К5. Плоскости комнаты (Quest 2/3, если К0 подтвердил)
Из `detectedPlanes` (вертикальные `wall`, пол) — отпечаток: углы и длины стен в системе шлема. Сравнение с `places.walls` → кандидаты `cal` (до 4 из-за симметрии); выбирается согласный с У2/У4. Сам по себе `cal` не даёт; служит проверкой дрейфа: расхождение со стенами > 10 см → `cal` под сомнение.

### К6. Камера по меткам (Quest 3, только если К0 показал кадры во время VR) — ревью Opus обязательно
`js/camtags.js` + Worker `js/camtags.worker.js`: `getUserMedia` → `ImageBitmap` 2–5 раз в секунду → поиск AprilTag (WASM-порт apriltag; лицензию и размер проверить до подключения, иначе свой детектор квадратов + декодер 36h11 на JS) → углы метки → положение метки относительно камеры (решение PnP по 4 углам, размер 18 см). Сдвиг камеры относительно головы и поле зрения — разовая калибровка на модель шлема (`camModel['Quest 3']`), подбирается по разметке К2: учитель смотрит на размеченные метки, мы подгоняем параметры, пока камера и касания не совпадут. Каждое наблюдение — поза головы в момент кадра (`timestamp` кадра → ближайшая `XRViewerPose` из буфера 0,5 с) + поза метки → оценка `cal`; фильтр: медиана по 10 наблюдениям, ≥ 2 разные метки, ошибка повторного проецирования < 1,5 см. Если в браузере камеры нет — **У1 не делаем**; отдельное нативное приложение (Passthrough Camera API Meta) — только отдельным решением владельца: у него своя система координат, и совместить её с браузером без общих якорей нельзя.

### К7. Сведение уровней и интерфейс
`js/anchor.js` (`VR.anchor`): источники → `cal` + доверие + возраст; правила раздела 0.4; значок в HUD (🟢 высокое / 🟡 среднее / 🔴 нет); у учителя на планшете (Т7) — список учеников с доверием калибровки, кнопка «Попросить откалиброваться». Проверки: чистые функции сведения (расхождения, вытеснение, возраст), e2e — имитация XR (`tests/e2e_net.py`) с подменой источников.

## 3. Порядок

К0 (Айрат) → К1 → К2 и К3 (параллельно: разные файлы) → К4 → К5 → К6 (если есть камера) → К7. Для Quest 1/2 полезный результат уже после К3 (касание любой пары меток) и К4 (Quest 2 — автоматом после первого раза).

## 4. Риски

1. **Дрейф отслеживания** шлема за урок (обычно сантиметры, при потере отслеживания — больше): У1/У3 ловят, без них — повтор касания по просьбе учителя.
2. **Карта помещения Quest** (на ней держатся якоря) сбрасывается при смене границы/очистке — якорь не найдётся, откат к К3; ничего не ломается.
3. **Камера в браузере Quest** — экспериментальная, может отличаться между версиями ОС: всё под флагом, при любой ошибке — молча к другим уровням.
4. **Освещение и печать** для У1: матовая бумага, метка не меньше 15 см, без бликов; проверка «видно ли метку» в режиме разметки.
5. **Неверная метка при касании** (ученик коснулся не той): сверка расстояния (К3) и ближайшей пары.
